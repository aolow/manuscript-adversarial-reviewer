# Two public-paper showcases

These examples show the full path from noisy automated leads to a shorter,
evidence-checked scientific review. Each combines an **actual offline MAR run**
with a **separately authored model-native synthesis** using the
[MAR skill](https://github.com/aolow/mar-skill/tree/a8406f6eae748f2788349dd524598d62dab23e68).

| Showcase | What it demonstrates | Start here |
| --- | --- | --- |
| **Single-cell foundation models** | Respect an explicitly scoped benchmark; distinguish a useful objection from something the authors already address | [Overview](single-cell-foundation-models/README.md) · [Full review](single-cell-foundation-models/review.md) |
| **Virtual Biotech** | Trace spatial, clinical and computational evidence to the exact claim it supports; turn uncertainty into a specific next check | [Overview](virtual-biotech/README.md) · [Full review](virtual-biotech/review.md) |

The first reviews the **published April 2025 article**. The second reviews the
**23 February 2026 preprint v1**, not its later Science version. Both are public
papers. Neither is an author-endorsed review or an editorial recommendation.

## What actually ran

| | Single-cell models | Virtual Biotech |
| --- | ---: | ---: |
| Extracted source blocks | 80 | 150 |
| Offline engine leads, all preserved | 32 | 30 |
| Model-native review items, including strengths and rejected leads | 10 | 11 |
| Exact evidence anchors checked | 20 | 27 |
| Provider-panel calls | 0 | 0 |

The scientific reviews were written in a Codex conversation. They were not
generated by the CLI's six-role provider panel and are not imported as accepted
engine findings. One model considering multiple lenses is not independent peer
review. The model also checked its own proposed concerns against counterevidence;
**no independent human adjudication has been performed**.

All 62 engine leads receive a visible model-native triage recommendation. The raw
engine dispositions are preserved. Several leads are plainly contextual false
positives or out of scope; others remain verification tasks. These counts are
not precision/recall estimates, and the cases are not a held-out benchmark.

## Reproduce the offline outputs and evidence checks

From the repository root, using Python 3.9+:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[test]"
python scripts/showcases.py all --download
```

The explicit `--download` fetches the two pinned public JATS XML articles from
Europe PMC over HTTPS. It does not send a manuscript to a model provider. The
script verifies each SHA-256 before parsing and fails on source drift. For one
case, replace `all` with `single-cell-foundation-models` or `virtual-biotech`.

After the first download, rerun entirely from the local cache:

```bash
python scripts/showcases.py all
```

Every run creates a new directory under ignored `reviews/showcases/runs/` with:

- The normalized manuscript and its JATS source index.
- The actual CLI `report.json` and `report.md`, including the full local audit.
- A source-free baseline projection and verification receipt.

The script compares the stable projection against the checked-in baseline,
checks all 47 quote spans against both the pinned source and MAR blocks, verifies
that every baseline lead is triaged exactly once, and checks that the readable
review matches its JSON. It never silently updates a baseline or overwrites a
prior run. Run IDs and timestamps naturally differ.

**Reproducible:** extraction, offline findings, provenance links and exact quote
spans. **Not reproduced by the script:** the model-native reasoning, scientific
conclusions, original experiments, or an LLM panel run. Exact quotation proves
text presence, not that a concern follows from it. Future engine or converter
changes may intentionally fail the baseline comparison and need explicit review.

## What is included—and what remains to check

Each directory contains a readable overview and review, a structured `review.json`,
all offline leads in `baseline.json`, source/version/license hashes in `source.json`,
and an actual run receipt in `provenance.json`.

The input includes abstracts, main text, methods, availability statements and
figure captions. External supplementary files, figure images, original code and
data were not inspected. Supplement *descriptions* are available for checking
whether the paper reports a sensitivity analysis; they do not establish its
result. Flattened equations are not used here to diagnose formula errors.

The benchmark paper's published peer-review history was not read. It remains a
possible later comparison, with the caveat that referees may have reviewed earlier
drafts. These examples should not be described as recovering or outperforming
those reviews.

## Lessons for MAR development

These cases expose useful regression targets: scope reporting cues to the correct
study and subject; avoid activating original-screen rules for cited future work;
recognize explicitly reported comparators and cutoffs; distinguish temporal
“first” from a novelty claim. The current engine outputs are left intact so a
future improvement can be compared transparently. Do not tune on these two cases
and then report performance on them as independent validation.
